# 章节创作工作流

## 1. 写前上下文

读取顺序：

1. 用户本次要求。
2. 最近三章摘要。
3. 当前故事弧和当前卷的相关部分。
4. 本章出现人物的状态。
5. `state/goldfinger.json` 中与本章相关的技能阶段、融合路线和材料。
6. 与地点、能力、法宝和伏笔有关的检索结果。
7. 仅在相关时读取 `state/humor.json` 中的近期重要事件、活跃回收项和受保护情绪；需要专项判断时读取 `references/humor-engine.md`。
8. 硬规则和作者明确禁区。

只有存在疑点时才回读旧正文。

## 2. 章节简报

简报保持短小：

- 本章临时标题。
- 当前局势。
- 主要行动者和欲望。
- 直接阻力。
- 本章必须遵守的事实。
- 可自由发挥的空间。
- 可能推进的承诺。
- 相关技能或融合条件，以及本章是否真的需要成长兑现。
- 不希望重复的近期模式。
- 当前场景模式、可回收的长期笑点和仍需保护的重大情绪；没有相关内容时保持为空。

不要在简报中规定所有对白、笑点和转折，也不要为本章设置固定笑点数量。

## 3. 场景生成

每个场景至少让一项发生变化：

- 信息。
- 权力。
- 关系。
- 目标。
- 风险。
- 地点或资源。
- 人物对自己的理解。

若一个场景结束后一切与开始时相同，应删除、合并或让它承担人物关系价值。

## 4. 对话

对话不是信息传送带。检查：

- 每个人说话时想达成什么。
- 是否有人理解错、回避或只回答一部分。
- 不同人物是否拥有不同句式和关注点。
- 重要信息是否能通过行动、物件和反应表现。
- 笑点是否来自说话者，而不是作者借所有人说同一种段子。
- 对话中的幽默是否仍在推动目标、关系或信息，而不是暂停场景表演。

## 5. 战斗

轻松文的战斗仍需清楚：

- 双方目标不必都是杀死对方。
- 地形、规则、资源和旁观者应影响选择。
- 聪明取胜必须建立在读者已知或可回溯的条件上。
- 喜剧可以来自战术和后果，但不能抹掉真正的危险。
- 战斗结果应改变后续关系、名声、资源或责任。

## 6. 章末

章末可选择：

- 新决定。
- 新信息。
- 关系变化。
- 小目标达成后的更大后果。
- 情绪余韵。
- 自然进入下一行动。
- 真正需要时的危机。

不要默认用半句话悬停。

## 7. 写后摘要

摘要应记录事实，不评论文笔。包含：

- 本章发生的主要事件。
- 人物状态变化。
- 新增事实。
- 新开、推进、兑现或放弃的承诺。
- 技能阶段、融合线索、桥梁功法或材料的真实变化。
- 时间和地点。
- 本章主要情绪、场景模式与喜剧来源。
- 只有需要长期追踪时才记录重要幽默事件、回收项、失效模式和情绪保护变化。
- 下一步候选可能性；明确标记它们不是事实。

## 8. 改写原则

用户只指出某个问题时：

1. 标出原文有效部分。
2. 找到造成问题的最小范围。
3. 只重写必要段落。
4. 检查修改是否改变事实。
5. 若事实改变，更新提交数据。

不要因为一句“这段不够好”就把整章换成另一篇完全不同的正文。
